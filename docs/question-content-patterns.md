# راهنمای کامل: انواع سؤالات و الگوهای صحیح نمایش آن‌ها در سایت

**هدف این سند:** اگه یک نشست جدید (چت جدید) با Claude شروع می‌شه و قراره روی بانک سؤالات کار بشه، این فایل رو اول بخون — همه‌ی الگوها، اشکالات رایج، و روش درست پیدا/اصلاح کردنشون اینجا مستنده.

منبع اصلی و تنها مرجع درست: `/mnt/user-data/uploads/Pruefungsfragen_AZ-900_De.pdf` (صفحه‌ی N = سؤال ۵۶۵-N). **هیچ‌وقت** بدون تطبیق مستقیم با این فایل، پاسخ یا محتوایی رو عوض نکن — فقط با نقل‌قول شفاهی («معلم گفت»، «فلان سایت گفت») کافی نیست، مگه با شواهد فنی مستقل (مثل مستندات رسمی Microsoft Learn) تأیید بشه.

## ۱. انواع سؤالات (Question Types)

فایل اصلی: `lib/az900Practice.ts` (برای AZ-900) و مشابهش برای AB-900.

### ۱.۱ تک‌گزینه‌ای (`type` حذف‌شده یا `"single"`)
ساختار: `prompt` + `options: [{id, text}]` + `correct: "A"|"B"|...`

### ۱.۲ بله/خیر چندگزاره‌ای (`type: "yesno"`)
ساختار: `statements: [{text, correct: "Ja"|"Nein"}]` + `combinedOptions: string[][]` (لیست تمام ترکیب‌های ممکن Ja/Nein، برای دکمه‌ی «انتخاب مستقیم ترکیب»)

### ۱.۳ تطبیقی (`type: "matching"`)
ساختار: `items: [{id, label}]` (ستون قابل‌کشیدن) + `descriptions: [{id, text, correctItemId}]` (ستون توضیح) + `combos?: string[][]` (اختیاری، برای دکمه‌ی «انتخاب مستقیم»)

**نکته‌ی مهم:** بعضی سؤالات تطبیقی، آیتم‌های «فریبنده» دارن که توی هیچ ترکیب واقعی استفاده نمی‌شن (طبق متن خود PDF: «هر مورد می‌تونه یک‌بار، چند بار یا اصلاً استفاده نشه»). این آیتم‌ها رو باید توی `items` نگه داشت (چون واقعاً توی لیست کشیدنی PDF هستن)، ولی نباید براشون combo ساختگی درست کرد.

### ۱.۴ جای‌خالی تک (blankFill)
برای سؤالات «جمله رو کامل کن» که همه‌ی گزینه‌ها ساختار مشترک دارن (فقط یک بخش فرق می‌کنه). فیلد اضافه به سؤال تک‌گزینه‌ای:
```ts
blankFill: { template: string /* شامل ___ */, choices: string[] /* هم‌ترتیب با options */ }
```

### ۱.۵ جای‌خالی چندتایی (blankFillMulti)
برای سؤالاتی با ۲-۳ جای خالی هم‌زمان (مثل سؤالات ترتیب‌چینی، یا انتخاب هم‌زمان چند مقدار):
```ts
blankFillMulti: { template: string /* چند ___ */, blanks: string[][], combos: number[][] }
```

## ۲. چک‌لیست تشخیص اشکال‌های رایج

### ۲.۱ «باگ جابه‌جایی متن» (Shift Bug) — شایع‌ترین اشکال
نشونه: یک گزینه بیش‌ازحد طولانیه (دو جمله‌ی مرتبط‌نشده بهم چسبیده)، گزینه‌ی بعدی خیلی کوتاه و بی‌معناست (فقط چند کلمه‌ی آخر یک جمله).

**روش اسکن خودکار:**
```python
# میانگین طول گزینه‌ها بالا ولی حداقلش خیلی پایین = نشونه‌ی این باگ
if avg(lens) > 35 and min(lens) < 16: flag_as_suspect
```
سپس با PDF تطبیق بده و بازسازی کن.

### ۲.۲ بولت‌های چسبیده به هم
نشونه: چند آیتم فهرست (•) که باید هرکدوم خط جدا باشن، ولی با فاصله روی یک خط چسبیدن.
**راه‌حل:** بین هر «•» یک `\n` واقعی بذار (کد رندر از قبل `whitespace-pre-line` داره، فقط داده باید درست بشه).

### ۲.۳ فاصله‌ی اضافه دور خط‌تیره (Line-wrap artifact)
نشونه: `"China- Dienste"` به‌جای `"China-Dienste"` (فاصله‌ی اضافه بعد از خط‌تیره، ناشی از شکست خط توی PDF اصلی).
**⚠️ هشدار مهم:** این فاصله گاهی **درسته** — ساختارهای بیضی‌گون آلمانی («weder X- noch Y»، «X- und Y-») واقعاً باید فاصله داشته باشن. فقط زمانی حذفش کن که کلمه‌ی بعد از خط‌تیره **نه** `und`/`oder`/`noch`/`als` باشه.

### ۲.۴ فاصله‌ی اضافه پیش از نقطه/ویرگول
نشونه: `"wird . ("` به‌جای `"wird. ("`.
**⚠️ هشدار:** این الگو توی خود کد TypeScript هم پیش میاد (مثل `q.correct ? q.correct`) — هر اصلاحی باید **فقط داخل رشته‌های متنی** (بین گیومه) اعمال بشه، نه کل فایل.

### ۲.۵ عکس گم‌شده
نشونه: متن سؤال به «Antwortbereich»، «Diagramm»، یا «unten dargestellt» اشاره می‌کنه ولی `imageUrl` نداره.
**روش:** `pdfimages -png -f <page> -l <page> ... ` برای استخراج، بعد OCR (`tesseract`) برای بررسی محتوا و پیدا کردن واترمارک احتمالی.

**روش دقیق پاک‌کردن واترمارک** (خیلی مهم، چندبار امتحان‌شده و کار می‌کنه):
1. با اسکن تراکم رنگ ردیفی (نه کل تصویر) محدوده‌ی y واترمارک رو پیدا کن
2. توی همون محدوده، bounding box دقیق x/y رو با اسکن رنگ محدود پیدا کن (نه تخمینی)
3. یک مستطیل سفید **دقیقاً** روی همون محدوده بکش (نه بزرگ‌تر — ریسک پاک‌کردن متن واقعی مجاور)
4. با OCR دوباره چک کن که هم واترمارک رفته، هم متن واقعی سالم مونده
5. اگه چند بار امتحان کردی و نشد (متن واقعی همیشه آسیب می‌بینه)، بی‌خیال اون عکس بشو — بهتره یک عکس نداشته باشیم تا یک عکس خراب

### ۲.۶ سؤالات با ساختار جمله‌ی ناهمگون
بعضی سؤالات «تکمیل جمله» ۴ گزینه دارن ولی ساختار جمله‌شون کاملاً متفاوته (نه فقط انتهاش فرق کنه). این‌ها رو **نباید** به‌زور توی یک `blankFill` جا داد — این کار پاسخ رو گمراه‌کننده می‌کنه. این موارد رو با گزینه‌های کامل (بدون blankFill) نگه دار.

## ۳. روش بررسی صحت پاسخ («کدوم گزینه درسته؟»)

۱. اول مستقیم متن `Richtige Antwort: X` رو از PDF بگیر (`pdftotext -f <page> -l <page> ...`)
۲. اگه کاربر ادعای متفاوتی داره (از معلم، سایت دیگه):
   - فقط با تکرار ادعا، پاسخ رو عوض نکن
   - جستجوی مستقل (`web_search`) برای شواهد فنی مستقل (ترجیحاً مستندات رسمی Microsoft Learn) انجام بده
   - اگه شواهد مستقل و قوی پیدا شد (نه فقط بحث انجمن)، پاسخ رو با توضیح دقیق دلیل تغییر بده
   - اگه فقط بحث/اختلاف‌نظر جامعه بود (بدون منبع رسمی روشن)، پاسخ رسمی PDF رو نگه دار
   - **نمونه‌ی واقعی این تصمیم:** Q310 (Azure Functions/Logic Apps Statefulness) با مستندات رسمی Microsoft تغییر کرد؛ Q378 (Azure Files IaaS/PaaS) هم با چند منبع مستقل (ExamTopics + StudyX) تغییر کرد، چون استدلال فنی روشنی پشتش بود.

## ۴. اصل بنیادین (تکرار از گزارش‌های قبلی)

**هیچ‌وقت داده‌ی جعلی نساز.** اگه اطلاعاتی (تعداد سؤال، قیمت، لینک شبکه‌ی اجتماعی) واقعی نیست یا هنوز آماده نشده، به‌جاش صریح بگو «در حال آماده‌سازی» — هرگز عدد یا لینک ساختگی نذار.
