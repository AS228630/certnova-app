# پنل مدیریت (Admin Dashboard) — طرح و مشخصات فنی

**وضعیت:** ⏳ فقط طرح/مشخصات فنی — هنوز هیچ‌کدام از بخش‌های زیر پیاده‌سازی نشده‌اند.
این سند صرفاً برای این نوشته شده که ایده‌ها و تصمیم‌های گرفته‌شده در گفتگو با یک همکار دیگر گم نشوند، تا هر وقت زمان پیاده‌سازی رسید، از همین‌جا شروع شود.

## هدف کلی
تکمیل یک پنل مدیریت نهایی برای CertCoach که ابزارهای مدیریتی زیر را در یک‌جا و بدون شلوغی بیش از حد در دسترس بگذارد: کدهای ارجاع اساتید، مدیریت دانشجویان، فروش گروهی/سازمانی (B2B)، و یک بخش شخصی برای مدیریت مدارک شغلی (توضیح در بخش ۴).

---

## ۱. سیستم کد ارجاع اساتید (Teacher Referral & Coupon System)

### منطق کلی
- هر مدرس یک کد اختصاصی و ثابت دارد (مثلاً `ARND10`)، که روی همه‌ی گواهینامه‌های سایت یکسان کار می‌کند.
- دانشجو هنگام خرید/ثبت‌نام کد را وارد می‌کند و روزهای هدیه (پیش‌فرض: ۱۰ روز) به مدت اشتراکش اضافه می‌شود.
- کدها به حروف کوچک/بزرگ حساس نیستند (`arnd10` = `ARND10`).
- هر خرید با یک کد، در دیتابیس ثبت می‌شود تا سهم/کمیسیون مدرس (پیش‌فرض ۵۰٪) قابل محاسبه باشد.

### تغییرات پیشنهادی دیتابیس

مدل کد ارجاع:
```
TeacherCoupon {
  id, teacherName, code (unique), extraDays (default 10),
  commissionRate (default 50%), isActive, createdAt
}
```

فیلدهای اضافه‌شده به جدول اشتراک/خرید:
```
Subscription {
  ...existing fields,
  appliedCouponCode?, teacherId?,
  endDate  // با احتساب روزهای هدیه محاسبه می‌شود
  amountPaid, teacherCommission  // = amountPaid * commissionRate
}
```

### تجربه‌ی کاربری (Checkout)
- فیلد ورودی «Gutscheincode / Dozenten-Code» + دکمه‌ی «Einlösen»
- اعتبارسنجی از طریق API؛ در صورت معتبر بودن: پیام موفقیت + نمایش تاریخ جدید پایان اشتراک
- در صورت نامعتبر بودن: پیام خطای واضح

### پنل مدیریت مربوط به این بخش
- فرم ساخت کد جدید (نام مدرس + کد اختصاصی)
- تنظیم روزهای هدیه و درصد کمیسیون per کد
- جدول گزارش‌گیری: نام مدرس | کد | تعداد خرید موفق | درآمد کل | سهم مدرس
- **دسترسی رایگان اساتید:** امکان اعطای دسترسی رایگان ۱ ساله (قابل‌تمدید) به حساب خود مدرس، با یک کلیک
- **گزارش خودکار ماهانه:** ارسال ایمیل خودکار (Cron Job) در پایان هر ماه میلادی به مدرسین، شامل خلاصه‌ی فروش کدشان

## ۲. مدیریت دانشجویان (Student Management)
- لیست کامل کاربران: نام، ایمیل، تاریخ ثبت‌نام، نوع اشتراک، وضعیت فعال/غیرفعال
- ردیابی این‌که هر دانشجو با کد کدام مدرس ثبت‌نام کرده
- کنترل دستی: تمدید، لغو، یا تغییر دوره‌ی دسترسی توسط ادمین

## ۳. فروش گروهی و سازمانی (B2B / Group Sales)
- تعریف کد گروهی (Corporate Coupon) — مثلاً ۵۰ یا ۱۰۰ لایسنس هم‌زمان با تخفیف
- تخصیص یک پکیج دسترسی به گروهی از دانشجویان که از طریق یک مدرس/مؤسسه وارد می‌شوند
- این بخش صراحتاً برای **آینده** در نظر گرفته شده، نه اولویت اول پیاده‌سازی

---

## ۴. بخش «Karriere-Dokumente» — نکته‌ی مهم درباره‌ی ماهیت این بخش

این بخش با بقیه‌ی پنل فرق دارد: بر خلاف بقیه‌ی بخش‌ها که مربوط به کسب‌وکار CertCoach‌اند، **Karriere-Dokumente یک ابزار شخصی مالک پروژه است**، نه یک قابلیت برای دانشجویان یا مشتریان سایت.

منظور از این بخش:
- یک لینک/دکمه در پنل ادمین که مستقیماً به یک صفحه‌ی شخصی و محرمانه (رزومه/HR Landing Page) مالک پروژه وصل می‌شود — تا نیازی به تایپ جداگانه‌ی آدرس آن صفحه نباشد.
- از داخل همین صفحه، مالک پروژه می‌تواند: مدارک PDF شخصی (رزومه، Zeugnisse، گواهی‌ها) را آپلود/آپدیت کند، برای شرکت‌های خاص (مثلاً یک استخدام‌کننده در Siemens) یک کد دسترسی بسازد تا بخش قفل‌شده‌ی مدارک را ببینند، و لینک مستقیم صفحه را برای ارسال به کارفرماها کپی کند.

نکته برای پیاده‌سازی: چون این بخش داده‌ی شخصی و حساس (مدارک هویتی/رزومه) نگه می‌دارد، باید از همان اصول امنیتی سخت‌گیرانه‌ای که برای بقیه‌ی دیتابیس رعایت می‌شود پیروی کند (Row Level Security در Supabase، کدهای دسترسی با تاریخ انقضا) — و منطقی است که کاملاً از دید دانشجویان عادی سایت پنهان بماند.

## ۵. طراحی UI پنل (بر اساس بازخورد روی ماک‌آپ اولیه)

یک طرح بصری اولیه (mockup) برای Dashboard بررسی و امتیازدهی شد: UI ۱۰/۱۰، UX ۹.۵/۱۰. بازخورد مشخصی هم برای بهبود ثبت شد که باید موقع پیاده‌سازی واقعی رعایت شود:

- **صفحه‌ی اول شلوغ نشود:** سه جدول هم‌زمان (اساتید، دانشجویان، B2B) در یک صفحه لازم نیست — فقط خلاصه‌ی هرکدام، با کلیک به صفحه‌ی اختصاصی برو.
- **Quick Actions اضافه شود:** دکمه‌های میان‌بر برای کارهای روزمره — «Dozenten-Code جدید»، «B2B Lizenz»، «Coupon»، «Hidden Link».
- **بخش System-Status کوچک‌تر شود:** یک کارت کوچک کافی است، نیازی به فضای زیاد نیست.

ساختار پیشنهادی منوی کناری (Sidebar):
```
📊 Dashboard
🎟️ Dozenten-Codes
👨‍🎓 Studenten
🏢 B2B & Gruppen
📁 Karriere-Dokumente   (شخصی — بخش ۴)
—
💳 Zahlungen / Abonnements / Auszahlungen / Transaktionen
—
📧 E-Mails & Vorlagen / Berichte & Exporte / Benachrichtigungen
—
⚙️ Einstellungen / Audit Logs / System-Status / Backup & Restore
```

## اولویت‌بندی پیشنهادی برای شروع پیاده‌سازی
این سند خودش تصمیم‌گیری نمی‌کند کدام بخش اول ساخته شود — این باید در یک نشست جدا مشخص شود. پیشنهاد منطقی بر اساس وابستگی فنی:
1. مدل دیتابیس کد ارجاع + منطق Checkout (چون بقیه‌ی گزارش‌گیری‌ها به این وابسته‌اند)
2. جدول گزارش‌گیری ادمین برای کدها
3. مدیریت دانشجویان
4. Karriere-Dokumente (مستقل از بقیه، می‌تواند هر زمان جدا انجام شود)
5. B2B/Gruppen (صراحتاً برای آینده)

## نکته برای نشست‌های بعدی
اگر این چت جدیدی شروع می‌کنی و می‌خواهی پیاده‌سازی این طرح را شروع کنی: این فایل فقط مشخصات فنی و طرح UI است، **کدی هنوز نوشته نشده**. اول با مالک پروژه هماهنگ کن که کدام بخش (از لیست اولویت‌بندی بالا) اول ساخته شود، چون این حجم کار برای یک نشست زیاد است.
