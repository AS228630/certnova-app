# گزارش کامل پروژه AB-900 و راهنمای شروع MD-102

## ۱. خلاصه‌ی اجرایی

بانک سؤالات **AB-900 (Microsoft 365 Copilot and Agent Administration Fundamentals)** به‌طور کامل تکمیل شد: **۱۰۲ از ۱۰۲ سؤال**، همه با متن آلمانی، توضیح کامل (Explanation)، لینک منابع رسمی مایکروسافت، و در مواردی که لازم بود، عکس واقعی (بدون واترمارک). صفحه‌ی معرفی این سرتیفیکیت الان برای گوگل قابل ایندکسه.

این گزارش برای این نوشته شده که تو چت بعدی، وقتی می‌خوای رو سرتیفیکیت بعدی (**MD-102 — Endpoint Administrator**) کار کنیم، همین دقیقاً روش و قوانین رو تکرار کنیم — بدون این‌که دوباره از صفر توضیح بدیم.

## ۲. مشکل مهمی که پیدا و حل شد (خیلی مهم برای MD-102)

**شماره‌ی نمایشی سؤال‌ها رو سایت بر اساس *موقعیت فیزیکی تو آرایه‌ی کد* حساب می‌شه، نه بر اساس رشته‌ی `id`.**

یعنی اگه یه سؤال با `id: "real-md102-50"` تو کد فیزیکاً جای بیستم آرایه نشسته باشه (نه جای پنجاهم)، رو سایت به‌عنوان سؤال «۲۰» نمایش داده می‌شه، نه «۵۰» — صرف‌نظر از این‌که `id`ش چی نوشته.

تو AB-900 این باعث یه باگ جدی شده بود: یه سؤال قدیمی (`real-ab900-102`) از یه جلسه‌ی خیلی قبل‌تر، به‌اشتباه نزدیک ابتدای آرایه (جای سوم) نشسته بود، و همین باعث می‌شد **همه‌ی سؤالات از شماره‌ی ۴ به بعد، یک واحد جلوتر از جای واقعی‌شون نمایش داده بشن.**

**قانون طلایی برای MD-102:** بعد از هر بار که یه سؤال رو کامل کردیم، همیشه با این اسکریپت چک کنیم که موقعیت فیزیکی هر `id` واقعاً با عددش یکی باشه:

```bash
node -e "
const fs = require('fs');
const content = fs.readFileSync('lib/md102Practice.ts', 'utf8');
const ids = [...content.matchAll(/id: \"(real-md102-[^\"]+)\"/g)].map(m => m[1]);
console.log('Total:', ids.length);
let mismatches = [];
for (let n = 1; n <= ids.length; n++) {
  const idx = ids.findIndex(id => id === 'real-md102-' + n);
  if (idx === -1) { mismatches.push('id'+n+' MISSING'); continue; }
  if (idx + 1 !== n) mismatches.push('id'+n+' at position '+(idx+1)+' (expected '+n+')');
}
console.log('Mismatches:', mismatches.length ? mismatches : 'NONE - perfect 1:1 mapping!');
"
```

## ۳. روش‌کار و قوانینی که تو AB-900 جا افتاد (عیناً برای MD-102 هم اعمال می‌شه)

### ۳.۱ تطبیق شماره‌گذاری
همیشه بر اساس ستون **«X of N»** (مثلاً «۷۱ of 102») با `real-<cert>-X` تطبیق می‌دیم، نه برچسب «Question: N» بالای صفحه (چون تو منبع بعضی شماره‌ها جا افتاده یا تکراریه).

### ۳.۲ اگه محتوای موجود مطابقت داشت
فقط فیلدهای ناقص رو کامل می‌کنیم — چیزی که از قبل درست بود رو دست نمی‌زنیم.

### ۳.۳ اگه محتوای موجود مطابقت نداشت (سؤال «جابه‌جا شده»)
محتوای درستی که فرستادی رو دقیقاً سر همون جایگاه آرایه (`real-<cert>-X`) جایگزین می‌کنم. سؤال قدیمی‌ای که اونجا بود رو با شناسه‌ی موقت `real-<cert>-X-displaced-<توضیح-کوتاه>` می‌برم **انتهای واقعی آرایه** (نه فقط یه جای دلبخواه وسط کد) — تا وقتی جای واقعیش رو فرستادی، اونجا برش گردونم.

### ۳.۴ انواع سؤال (structure دقیق تو `lib/practiceTypes.ts`)

| نوع | کِی استفاده می‌شه | فیلد کلیدی |
|---|---|---|
| **Single-choice** | سؤال معمولی تک‌جوابی | `options` + `correct: "A"` |
| **Multi-select** | «دو/سه گزینه رو انتخاب کنید» | `correct: ["B", "C"]` |
| **blankFill** | جمله با یک خانه‌ی خالی (dropdown) | `blankFill: { template, choices }` — `choices[i]` باید دقیقاً با `options[i]` هم‌ترتیب باشه |
| **blankFillMulti** | جمله با ۲-۳ خانه‌ی خالی هم‌زمان | `blankFillMulti: { template, blanks, combos }` — `combos[i]` = شماره‌ی انتخاب هر خانه که `options[i]` رو می‌سازه |
| **yesno** | «برای هر Aussage بله/نه انتخاب کنید» | `type: "yesno"`, `statements: [{text, correct: "Ja"|"Nein"}]` **+ حتماً `combinedOptions`** (۶ گزینه‌ی A-F دقیقاً مثل سورس، هرکدوم یه آرایه‌ی Ja/Nein هم‌ترتیب با `statements`) |
| **matching** | کشیدن‌ورهاکردن (drag & drop) | `type: "matching"`, `items`, `descriptions`, `combos` |

⚠️ **نکته‌ی مهمی که چند بار فراموش شد:** سؤالات `yesno` بدون `combinedOptions` فقط تیک بله/نه تک‌تک رو نشون می‌دن، نه ۶ گزینه‌ی A-F ترکیبی که تو امتحان اصلی هست. **همیشه از همون ابتدا `combinedOptions` رو هم بساز**، دقیقاً با ترتیب A تا F که تو متن اصلی سؤال اومده (این ترتیب همیشه یکی نیست — هر بار از رو متن واقعی چک کن، حدس نزن).

### ۳.۵ عکس‌ها
- هر عکسی که تو `public/exam-images/` ذخیره می‌شه، اگه واترمارک روش باشه (مثلاً `www.cert2brain.com`)، **قبل از ذخیره‌ی نهایی** با پایتون/PIL پاک می‌شه — مختصات دقیق واترمارک رو با `numpy` پیدا می‌کنم (رنگ آبی مشخص)، نه با حدس چشمی.
- عکسی که فقط UI یه dropdown خالیه (نه یه exhibit واقعی مثل نمودار، جدول تنظیمات واقعی، یا اسکرین‌شات یه پنل ادمین با داده‌ی واقعی) اصلاً ذخیره نمی‌شه — چون `blankFill` خودش اون UI رو می‌سازه.
- عکس‌های واقعی exhibit (جدول‌ها، پنل‌های تنظیمات با مقادیر واقعی، نمودارها) ذخیره و به `imageUrl` (رو خود سؤال) یا `explanationImageUrl` (زیر متن توضیح) وصل می‌شن — بسته به این‌که عکس بخشی از خود سؤاله یا فقط مکمل توضیحه.

### ۳.۶ چک‌های اجباری قبل از هر push
هر بار (نه فقط قبل از push):
```bash
npx tsc --noEmit -p .
npx eslint lib/md102Practice.ts
```
قبل از push هم یه `npm run build` کامل با env vars موقت:
```bash
export NEXT_PUBLIC_SUPABASE_URL="https://placeholder.supabase.co" \
  NEXT_PUBLIC_SUPABASE_ANON_KEY="placeholder-anon-key" \
  SUPABASE_SERVICE_ROLE_KEY="placeholder-service-role-key"
npm run build
```

### ۳.۷ توکن گیت‌هاب
هر توکن فقط یک‌بار مصرف — بعد از هر push، بلافاصله باید تو `github.com/settings/tokens` باطل (Revoke) بشه و برای push بعدی یه توکن تازه ساخته بشه.

### ۳.۸ الگوی push
هر ۱۰ سؤال یه‌بار (یا هر وقت خودت بخوای) — ولی هیچ‌وقت بیش از حد صبر نکن؛ اگه چند سؤال پشت‌سرهم کامل شد و push نشد، حتماً یادآوری می‌کنم که کار ذخیره‌نشده رو دیسک مونده و ریسک از دست رفتنش هست.

## ۴. وضعیت فعلی AB-900 (تکمیل‌شده)

- **۱۰۲ از ۱۰۲ سؤال** کامل، هیچ سؤال displaced باقی نمونده
- موضوع‌بندی (Topics):
  - Microsoft 365 Copilot Grundlagen: ۲۸ سؤال
  - Copilot-Agenten verwalten: ۱۲ سؤال
  - Sicherheit und Identität: ۲۰ سؤال
  - Purview und Compliance: ۲۷ سؤال
  - Verwaltung und Governance: ۱۳ سؤال
  - Verantwortungsvolle KI: ۲ سؤال
- فایل اصلی: `lib/ab900Practice.ts`
- ترجمه‌های ۹ زبونه (`lib/i18n/questions/ab900.*.ts`) هنوز کامنت قدیمی «۱۰۱ از ۱۰۱» دارن — چون سؤال ۳ و ۱۰۲ امروز عوض شدن، این ترجمه‌ها به‌روز نیستن؛ اگه خواستی می‌تونیم بعداً جدا روش کار کنیم.
- صفحه‌ی معرفی AB-900 برای گوگل ایندکس فعال شد؛ ۵ سؤال نمونه (id های ۴، ۶، ۷، ۸، ۱۴) عمومی نشون داده می‌شن.
- یه فیچر UI هم اضافه شد: دکمه‌ی جمع‌کردن سایدبار (کنار لوگو، تو Header سراسری) — رو همه‌ی صفحات کار می‌کنه.

## ۵. وضعیت MD-102 (شروع‌نشده)

- تو `lib/companiesData.ts` دو ورودی MD-102 پیدا شد:
  - `id: "md-102"` — عنوان «Endpoint Administrator»
  - `id: "md-1021"` — عنوان «Endpoint Administrator Associate»
  
  اینا احتمالاً دو نسخه‌ی متفاوت یا یه تکرار اشتباهی‌ان — تو چت بعدی باید اول مشخص کنیم کدوم `certId` درسته، یا هر دو باید بمونن.
- هیچ فایل `lib/md102Practice.ts` یا بانک سؤال واقعی وجود نداره — باید از صفر ساخته بشه، دقیقاً با همون ساختار `AB900_TOPICS` + `AB900_QUESTIONS` که تو `lib/ab900Practice.ts` هست (فقط اسم‌ها عوض بشه).
- `hasPracticeBank()` تو `lib/server/practiceBank.ts` باید MD-102 رو به‌عنوان دارای بانک واقعی بشناسه، وگرنه صفحه‌ش `ComingSoonPractice` نشون می‌ده به‌جای Practice واقعی.
